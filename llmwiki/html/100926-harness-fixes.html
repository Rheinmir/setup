01 · GH#150

CI đỏ ở R3 index-sync

Commit 6a1024d — hook wiki-index-sync đưa vào pre-commit.

Triệu chứng

  • CI job harness đỏ ở bước R3 index-sync, commit 8f0a24f
  • Log ghi thiếu trong index: sources/draft/100926-install-seed-skipped-on-migrate.md
  • Working tree máy vẫn xanh — vì hook đã tự chèn dòng mà chưa commit

Gốc (đã đo)

  • Commit 52f3334 thêm draft mà quên dòng index vào index.md
  • HEAD 9cd53d0: grep -c → 0, bản đã commit đỏ thật
  • R3 bị dời sang CI theo issue #18 — bộ fire-drill đầy đủ không chạy mỗi commit
Đo: R3 mất 2.26s cho llmwiki/wiki, 0.71s cho fdk/wiki — rẻ, nên đưa lại pre-commit.

Sửa

  • Commit dòng index còn thiếu
  • Thêm hook wiki-index-sync vào pre-commit, chỉ chạy khi đổi ^(fdk|llmwiki)/wiki/.*\.md$
  • Giữ tinh thần #18: không chạy cả bộ mỗi commit, vẫn chặn đúng lớp lỗi

Bằng chứng

  • Fire-drill: draft mới stage, index KHÔNG stage → Failed rc=1
  • Stage dòng index → Passed rc=0
  • Pre-commit stash phần chưa stage trước khi chạy hook
Nợ mở: prompt CI yêu cầu nhãn ready-for-agent nhưng repo chỉ có ready-for-human.

  • tester-kit: 11 phiên có số đo, 0 biên lai okf-scan

03 · Context window

Cơ chế "đầy context thì tự xoay phiên" chưa từng chạy

Commit 7803210 — sửa phép tính dùng cả cache_read + cache_creation.

Triệu chứng

  • self-report ghi "bàn giao tự động 0" trên phiên dài 367 lượt
  • Context thật lượt cuối = 613 246 token nhưng cơ chế không bao giờ kích hoạt
  • Chỉ 3 866 ra từ phép tính cũ → luôn ~15% trần 2 000 000

Gốc (đã đo)

  • Cơ chế gác cũ chỉ cộng input_tokens (3 866)
  • Với prompt cache, độ đầy context nằm ở cache_read (606 145) — đã bị bỏ
  • Bỏ cache_read là ĐÚNG khi tính tiền, nhưng SAI khi tính context
Giới hạn: cơ chế chỉ bắn ở ~850k. Nếu Claude Code tự nén context trước mốc đó thì vẫn im.

Sửa

  • trigger context_window_tokens đọc usage lượt cuối trong transcript
  • Cộng: input_tokens + cache_read_input_tokens + cache_creation_input_tokens
  • So với cửa sổ 1 000 000 × ngưỡng 0.85 = 850 000

Bằng chứng

  • Phiên 367 lượt: 32 + 606 145 + 7 069 = 613 246 token
  • Cũ: 3 866 / 2M ≈ 15% → không kích hoạt
  • Mới: 613 246 / 850k ≈ 72% → sẵn sàng kích hoạt khi chạm ngưỡng
